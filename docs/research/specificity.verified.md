## Bugs in specificity_reference.py (fixed in specificity_reference_fixed.py)

1. Designed pairs that amplify extra copies are labelled "intended". `intended` was "designed pair and both sites perfect", with no coordinate check. A023, A071 (second genomic copy) and A026 (1700 bp product between repeated perfect sites) were therefore counted among the 103 intended products and escape the recommended rule "replace a primer that creates any unintended likely product". Fix: optional `targets={(i, j): (contig, start, end)}` so only the designed product is intended; without targets, every intended product of a pair with more than one gets `extra_copy=True` (6 products flagged on the test pool).
2. The "possible" tier was incomplete. Only sites with score >= 0.01 entered product enumeration, so a product of a perfect site (score about 1) and an off-target site scoring 1e-4 to 0.01 was never reported. Fix: enumerate sites with score >= `product_possible` and drop products below it. Taq 65 C: possible products 191 -> 2,179; likely unchanged (175).
3. `merge_loci` chained sites. The window was measured from the previous site, so sites every <= 20 nt across a tandem repeat merged into one locus (9 sites spaced 15 nt: 1 locus; fixed: 5). Fix: measure from the first 3' end of each locus.

Not fixed, but worth knowing: thal raises RuntimeError if both sequences exceed 60 nt, so tailed amplicon-seq primers (gene-specific part plus 33 to 34 nt adapter overhang) will crash `score_sites` unless only the gene-specific part is checked; the report's recommendation to use the module unchanged needs this guard.

## Independent cross-checks

- Truth-set scores: 1,200 sites (Taq 60 C, proofreading 65 C) rescored with my own code calling primer3 directly; all match the module's stored scores exactly. The recall test is therefore internally consistent, but it measures search recall against the module's own scorer, not against wet-lab truth.
- Extension-factor orientation: planted A.A, A.C, A.G terminal mismatches on both strands; factors 0.01, 0.3, 0.01 as intended.
- NUPACK 4 vs thal: perfect 20-mers at 1 M Na+ differ by 2.44 (37 C) and 2.65 (60 C) kcal/mol, which equals RT ln(55.14), the NUPACK mole-fraction standard state. After that correction, NUPACK ensemble dG is still more negative than thal by 1.1 (perfect), 2.3 (1 to 3 mismatches) and 3.7 (4+ mismatches) kcal/mol on truth sites at 60 C, 50 mM Na+, 1.2 mM free Mg2+. A 2 kcal/mol shift moves theta about 20-fold, so the 0.01 cut-offs are model dependent. Anyone swapping in NUPACK energies must add RT ln(55.14) before using `frac_bound`.

## Points the report missed

- Single-pool tiling: overlapping amplicons in one pool always create short F(n+1)/R(n) products that this module reports as unintended likely products. The designer must either avoid overlaps in a single pool or treat these explicitly. The user asked for one pool with every position covered, so this matters.
- Literature tension with the Taq model: Lefever 2013 found >= 4 mismatches in one primer (or 3 + 2) were needed to block qPCR completely, so citing Lefever for a 0.01 cap at 2 mismatches in the last 5 overstates it. Rejali 2018 found a C.C mismatch 6 nt from the 3' end still cut extension rate by up to 84 %, and optimal extension temperature fell to 55 to 60 C for 3' mismatches, while the module gives positions >= 6 a factor of 1.0.
- Stadhouders 2010 Ct effects come from a 5' nuclease qPCR assay with up to sevenfold differences between master mixes; the abstract does not state the primer/template order of the pair notation.
- Per-primer concentration in large multiplex pools is often below 250 nM. Theta scales with C, so the dG threshold for theta 0.01 shifts by RT ln(C ratio), about 0.6 kcal/mol at 100 nM.
- BLAST speed: `-num_threads` does not help with one subject, but splitting the primer set across separate blastn processes would; the 5x to 13x speed gap is not inherent.
- `find_sites_blast` relies on `sseqid` matching the FASTA ID; this held for BLAST+ 2.16.0 in the module tests, but databases built with other options can report `gnl|BL_ORD_ID|n` IDs.
- Proofreading mode uses the ANY alignment even when it leaves a long unpaired 3' tail; Gohl 2021 shows editing reaches only 2 (Phusion) to 6 (KAPA HiFi) nt, so ext = 1 overstates risk for such alignments.
